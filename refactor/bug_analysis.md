# Bug分析：K线数据过滤和插入问题

## 问题1：历史数据过滤后为0

### 日志显示：
```
HistoricalDataService: filtered 0 K-lines for date 2025-11-23 (from 1439 total)
```

### 请求范围：
- `range: 1763879960156746 - 1763942400000000 us`
- 转换为日期：`2025-11-23 06:39:20` - `2025-11-24 00:00:00`

### 下载的数据：
- 日期：`2025-11-23`
- 数据范围：`2025-11-23 00:00:00` - `2025-11-23 23:59:59`
- 共1439条K线（1分钟K线，24小时 = 1440条，可能缺少1条）

### 过滤条件：
```rust
.filter(|k| k.open_time_us >= range.start_us && k.open_time_us < range.end_us)
```

### 问题分析：
- 11月23日的数据从 `2025-11-23 00:00:00` 开始
- 但请求范围从 `2025-11-23 06:39:20` 开始
- 所以11月23日00:00:00到06:39:20的数据应该被过滤掉
- 但11月23日06:39:20之后的数据应该还在范围内

### 可能的原因：
1. 下载的数据的时间戳不正确
2. 时间单位转换有问题
3. 数据的时间戳不在请求范围内

## 问题2：K线数据插入后数据范围只有单个时间点

### 日志显示：
```
KlineChart: data range: 1763966340000 - 1763966340000 ms
```

### 问题分析：
- `data range` 只有单个时间点，说明 `timeseries.datapoints` 只有一个数据点
- 但 `insert_klines` 应该插入多条数据
- 可能是数据转换或插入逻辑有问题

### 可能的原因：
1. `convert_to_exchange_kline` 转换有问题
2. `TimeSeries::insert_klines` 插入逻辑有问题
3. 数据的时间戳重复，导致覆盖

## 问题3：请求重复（Overlaps）

### 日志显示：
```
KlineChart: request handler error: Overlaps
```

### 问题分析：
- 因为数据一直没有更新，所以不断重复请求
- `RequestHandler` 检测到请求重叠，拒绝重复请求

## 解决方案

### 1. 修复历史数据过滤逻辑
- 添加调试日志，输出下载数据的时间范围
- 检查时间单位转换是否正确

### 2. 修复数据插入逻辑
- 添加调试日志，输出插入的数据数量和时间范围
- 检查 `convert_to_exchange_kline` 转换是否正确
- 检查 `TimeSeries::insert_klines` 是否正确插入数据

### 3. 修复请求重复问题
- 确保数据正确插入后，`last_visible_range` 被正确更新
- 确保 `check_data_update_needed` 正确检测数据覆盖情况
