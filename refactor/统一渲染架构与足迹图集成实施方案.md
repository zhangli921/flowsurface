

# **第四阶段实施方案：统一渲染架构、K线集成与足迹图（Footprint）高性能聚合**

## **I. 阶段目标与架构总览**

### **1.1. 阶段核心目标**

第四阶段是可视化集成和架构统一的终极目标。核心在于将第三阶段计算出的高性能数据（Session Volume Profile, S-VP）和现有功能（K线图、Footprint 足迹图、Heatmap 热力图）在同一个 **WGPU 渲染管线**中高效绘制，并完成 **Footprint (IBVP) 的 GPGPU 聚合**，实现所有高性能功能的统一架构。

* **统一渲染：** 实现一个分层（Layered）渲染架构，将所有图表元素（K线、S-VP 筹码峰、IBVP 足迹图）整合到 iced::widget::shader 的单一 WGPU 通道中。  
* **Footprint 聚合加速：** 将 Footprint Chart 所需的 **Intra-Bar Volume Profile (IBVP)** 聚合任务（即逐根 K 线的 Delta 成交量分布）也卸载到 GPGPU，使用稀疏数据结构保持内存效率。  
* **K 线融合：** 确保 K 线图（基础层）的渲染与 S-VP/IBVP（叠加层）的渲染在视觉和坐标系统上无缝衔接。

### **1.2. Footprint (IBVP) 的数据挑战**

Footprint Chart 需要计算每个价格级别在**单根 K 线内部**的买卖 Delta 1。这涉及一个 2D 聚合问题：价格 (Y 轴) $\\times$ 买卖方向/交易量 (值)。

* **数据结构：** 虽然是 2D 聚合，但由于每根 K 线内部的价格分布通常是稀疏的，因此必须采用**稀疏直方图**（Sparse Histogram）或类似的压缩数据结构来保存结果。  
* **计算：** 需要 GPGPU 计算内核对 K 线周期内的 Tick 数据进行**两次**原子累加（买入量和卖出量），然后 CPU 在后处理阶段计算 Delta。

## **II. GPGPU 扩展：Intra-Bar Volume Profile (IBVP)**

### **2.1. IBVP 计算的并行化策略**

Footprint 的 IBVP 聚合将作为 Session Volume Profile (S-VP) 的扩展任务，在 vp\_compute\_engine 模块内执行。

1. **输入数据：** 依然是可见范围内的 **Tick Data SoA 切片**（由 Mmap 驱动的 HostStagingBuffer 提供）。  
2. **GPU Kernel 设计：** 针对 IBVP，需要修改 WGSL 内核，增加一个时间/K 线索引维度。  
   * **并行原子累加：** 内核需要同时对买入量（Bid Volume）和卖出量（Ask Volume）进行原子累加，并确保累加只发生在当前 Tick 所属的 K 线的时间戳范围内 1。  
3. **调度优化：** IBVP 是“多次小聚合”而不是 S-VP 的“单次大聚合”。CPU 协调器需在 wgpu::Queue 中调度**多组** Compute Pass，或设计一个能够识别 K 线边界的更复杂的 2D Workgroup 调度策略，以避免大量的线程空闲。

### **2.2. IBVP 结果的稀疏数据结构**

为高效渲染和内存管理，IBVP 的 GPU 结果必须是稀疏的，且包含足够的定位信息。

Rust

// data/src/vp\_data/ibvp\_bar.rs  
// IBVP\_Bar 结构体 (用于实例渲染)  
\#\[repr(C)\]  
\#\[derive(Copy, Clone)\]  
pub struct IbvpBar {  
    // K线在屏幕上的 X 轴位置 (用于定位到正确的 K 线)  
    pub kline\_x\_index: u32,   
    // Y 轴价格级别  
    pub price\_level\_y: f32,   
    // 归一化买入量（左侧）  
    pub bid\_volume\_norm: f32,   
    // 归一化卖出量（右侧）  
    pub ask\_volume\_norm: f32,  
    // 颜色/状态 ID (例如，POC，Imbalance)  
    pub color\_id: u32,  
}

### **2.3. CPU 后处理：Delta 与 Imbalance 计算**

在 GPU 聚合完成后，CPU 的异步回调任务将对稀疏结果进行最终的金融分析 1。

1. **Delta 计算：** 对于每个价格级别，计算 Ask Volume \- Bid Volume。  
2. **Imbalance 检测：** 检查相邻价格级别上买入量与卖出量之间的比率，标记出显著的\*\*失衡（Imbalance）\*\*单元格。  
3. **结果返回：** 生成 Vec\<IbvpBar\>，包装在 Message::IbvpComputeResult 中返回给 iced 运行时。

## **III. 统一渲染架构：WGPU 渲染通道设计**

为了实现零开销叠加绘制，所有图表元素（K线、S-VP、IBVP）都将在一个共享的 WGPU **渲染通道（Render Pass）** 中绘制。

### **3.1. K 线图作为基础层 (kline\_renderer)**

K 线图作为所有叠加图表的基础，提供坐标系统和时间轴。

* **数据来源：** K 线图数据（OHLCV）来自 Stage II 的数据仲裁服务。  
* **渲染模式：** 传统的顶点/索引缓冲区绘制模式。K 线图的渲染器必须负责将时间/价格坐标系转换为标准的裁剪空间坐标，供后续叠加层使用。

### **3.2. S-VP 筹码峰渲染 (sv\_profile\_renderer)**

S-VP 绘制在图表的一侧，是水平的柱状图。

* **WGPU Instancing 强制要求：** S-VP 必须使用 **实例渲染（Instancing）** 来绘制 2。  
  * **基础几何体：** 渲染管线只需定义一个简单的单位矩形（一个直方图柱状条）。  
  * **实例缓冲区：** 接收 Vec\<SparseBar\>（来自 Stage III 计算结果），该数据包含每个柱状条的**位置**（price\_level\_y）和**宽度**（bar\_width\_norm）。  
  * **Vertex Shader：** 核心工作是将实例数据（位置、宽度）结合图表投影矩阵，计算出每个柱状条在屏幕上的最终 $X, Y$ 坐标和尺寸。

### **3.3. IBVP 足迹图渲染 (footprint\_renderer)**

IBVP 渲染是 Footprint Chart 的核心。它将 Footprint 单元格绘制在 K 线的内部。

* **渲染模式：** 同样使用 **实例渲染**。  
  * **实例缓冲区：** 接收 Vec\<IbvpBar\>（来自 Stage IV 计算结果）。  
  * **Vertex Shader：** 读取 kline\_x\_index 和 price\_level\_y，将单元格精确地放置在对应的 K 线内部的正确价格位置。  
  * **Fragment Shader：** 根据 color\_id（Delta 或 Imbalance 状态）为单元格着色，实现 Footprint Chart 的核心可视化效果 1。

### **3.4. 统一渲染通道的封装 (ChartRenderer)**

flowsurface-rs 的自定义 iced::widget::shader 组件（例如 ChartRenderer）将负责管理所有渲染子组件的顺序和状态。

Rust

// src/chart/renderer.rs (逻辑抽象)

### **3.5. 渲染透明度与深度**

由于 S-VP 筹码峰和 IBVP 足迹图都是**叠加**在 K 线图之上的半透明或不规则图形，渲染管线必须正确配置：

* **深度测试（Depth Testing）：** 对于 2D 图表，深度测试通常不用于隐藏对象，而是用于控制绘制顺序。  
* **Alpha 混合（Blending）：** 必须在渲染管线中启用 Alpha 混合，确保 S-VP 柱状条或 Footprint 单元格能够与下层的 K 线颜色正确混合，避免完全覆盖 K 线信息。

## **V. 鲁棒性与非偏离性检查**

### **5.1. 跨功能数据依赖**

Footprint (IBVP) 的渲染直接依赖于 K 线图的时间/价格坐标系。因此，所有渲染子组件必须共享一个**统一缓冲区（Uniform Buffer）**，该缓冲区包含最新的图表缩放、平移和价格分辨率参数。这确保了 S-VP 和 IBVP 的实例顶点着色器能够精确地将数据点映射到屏幕上的正确像素位置。

### **5.2. 避免 CPU 瓶颈的最终验证**

* **数据路径：** Tick Data (Mmap) $\\rightarrow$ Host Buffer (I/O 隔离) $\\rightarrow$ GPGPU (并行聚合) $\\rightarrow$ Sparse Instance Data (CPU 后处理) $\\rightarrow$ WGPU Instance Buffer (零拷贝渲染)。  
* **性能保证：** 最终渲染负载（S-VP 柱状条和 IBVP 单元格）被转化为 **GPU 实例渲染**，确保无论图表数据量多大，渲染性能都接近**恒定时间**（仅与屏幕上的实例数量相关，与原始 Tick 数量无关），彻底解决了 UI 性能过载的问题 2。
